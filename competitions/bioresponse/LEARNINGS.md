## 1. CV가 측정하는 것과 제출하는 것이 같아야 한다

가장 비싸게 배운 것. `baseline.py`는 이렇게 생겼었다.

```python
oof[va_i] = m.predict_proba(X[va_i])[:, 1]        # CV 점수 ← 모델 1개
test_pred += m.predict_proba(X_test)[:, 1] / 5    # 제출     ← 모델 5개 평균
```

**CV는 단일 모델을 재고, 제출은 앙상블로 한다.** 서로 다른 물건이다.
그래서 CV 1위였던 RF가 LB 371위, CV 꼴찌였던 XGB가 LB 49위로 뒤집혔다.

| | CV | Public LB | 갭 |
|---|---|---|---|
| RF | 0.46423 (1위) | 0.46180 | −0.0024 |
| XGB | 0.47682 (꼴찌) | 0.42016 | −0.0567 |

**다음에**: 제출 형태가 fold 평균이면 CV도 fold 평균으로 재야 한다.
못 하겠으면 최소한 "이 CV는 제출과 다른 것을 재고 있다"는 걸 의식하고 모델을 고른다.

## 2. 한 점으로 일반화하지 않는다

RF 하나만 제출해놓고 "CV−LB 갭이 −0.0024니 이 대회는 CV를 믿어도 된다"고 결론 내렸다.
XGB를 제출해보니 갭이 −0.0567, **23배**였다.

**갭은 대회의 속성이 아니라 모델마다 다르다.**
한 번 측정하고 일반화한 결론은 그 다음 측정에서 깨진다.

## 3. 변수를 하나만 바꿔야 비교가 된다

"nb01~03이 단일 모델로 제출해서 진 것"이라는 가설로 `04_fold_ensemble.py`를 만들었는데,
앙상블 여부 말고도 **전처리·fold 수·파라미터·blend 구성을 동시에** 바꿔버렸다.
결과가 나빠져도(3개 중 2개 악화) 어느 탓인지 알 수 없었다.

변수를 하나만 바꾼 `xgb_single.py`를 따로 돌려서야 결론이 났다.

| exp02 XGB | Public | Private |
|---|---|---|
| 5-fold 평균 | 0.42016 | 0.37939 |
| 전체 재학습 단일 | 0.43674 | 0.38552 |

**다음에**: 비교 실험을 만들 때 "내가 지금 몇 개를 바꾸고 있나"를 먼저 센다.
두 개 이상이면 실험이 아니라 그냥 다른 시도다.

## 4. Public LB를 믿지 않는다

`exp02b`는 **Public 131위인데 Private 2위**였다.
대회 진행 중이었다면 Public만 보고 버렸을 제출이다.

Public은 test의 일부에 대한 한 번의 채점일 뿐이다.
종료 대회라 Private이 바로 보여서 운 좋게 알아챘다.

## 5. 평가지표가 바뀌면 따라 바뀌는 것들

Accuracy → LogLoss로 오면서 실제로 걸린 것들.

- `predict`가 아니라 **`predict_proba`**, CV는 `scoring='neg_log_loss'`
- **점수 방향이 반대**다. 낮을수록 좋다
- **기준점을 먼저 계산해둔다** — all-0.5가 0.69315다. 이보다 나쁘면 파이프라인 버그다.
  이 숫자 하나로 디버깅이 몇 번 빨라졌다
- **AUC 순위와 LogLoss 순위가 다르다.** xgboost가 AUC 0.853(상위권)인데 LogLoss 0.596(최하위).
  순위는 잘 매기는데 확률 보정이 안 된 것. LogLoss에서는 그게 그대로 손실이다
- 보정이 이미 잘 된 모델(catboost)에 sigmoid 보정을 더하면 **나빠진다** (0.4700 → 0.4751)

## 6. 자동화 도구는 조용히 실패한다

PyCaret 노트북이 2분 만에 끝나길래 봤더니 **7개 중 4개만 학습**돼 있었다.
`errors="ignore"`가 lightgbm·xgboost·catboost 실패를 삼켰고, 결과는 정상처럼 나왔다.
재실행하니 **1위 모델이 rf → catboost로 바뀌었다.**

원인 연쇄가 고약했다.

```
pillow의 top_level.txt가 깨진 바이너리
 → importlib.metadata.read_text()가 UnicodeDecodeError
 → pycaret의 get_installed_modules()가 통째로 예외
 → 모든 soft dependency 체크가 False
 → 부스팅 컨테이너 3개가 early return
 → "Unknown model id 'lightgbm'"
```

pillow와 아무 상관없어 보이는 메시지가 뜬다.

**다음에**: 모델 비교 도구를 쓰면 **학습된 모델 개수를 눈으로 센다.**
실행 시간이 예상보다 짧으면 그게 첫 신호다.

## 7. EDA는 결정에 쓰여야 한다

Titanic에서 EDA를 건너뛴 게 아쉬워서 이번엔 제대로 했는데, 실제로 베이스라인 설계를 바꿨다.

- 결측 0, 전 피처 [0,1] → **전처리 코드를 아예 안 썼다**
- 상수·완전중복·near-constant 전부 0개 → **피처 제거 단계를 통째로 생략**
- 피처 간 \|r\|>0.9 쌍이 **정확히 0개**(최대 0.8999) → 주최측이 미리 제거해둔 것.
  상관 기반 제거도 불필요
- \|r\|>0.2인 피처가 12개뿐, 약한 신호가 넓게 분산 → 피처 선택보다 트리 앙상블

마지막 관찰이 나중에 **XGB의 `colsample_bytree=0.5`가 왜 잘 들었는지** 설명해줬다.
피처를 절반만 보게 강제하는 게 이런 구조에 맞았다.

**EDA 결과가 "그래서 뭘 바꿀 것인가"로 이어지지 않으면 안 한 것과 같다.**

## 8. polars로 wide CSV 읽을 때

1,776컬럼에서 두 번 걸렸다.

```python
# 기본 추론은 앞 100행만 본다 → D651을 i64로 잡고 ComputeError
pl.read_csv(path, infer_schema_length=None)

# 같은 컬럼이 train은 Int64 / test는 Float64로 추론돼 concat에서 SchemaError
pl.concat([train.cast(pl.Float64), test.cast(pl.Float64)])
```

쓸 만했던 것: `pl.all().n_unique()` 한 줄로 1,776컬럼 집계,
`transpose().is_duplicated()`로 중복 피처 탐지.
반대로 157만 쌍 전수 상관 같은 건 numpy 행렬곱이 압도적이다. **도구를 섞어 쓰는 게 맞다.**
