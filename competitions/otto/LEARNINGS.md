# Otto — 배운 것

3회차. [[Titanic-진행기록|Titanic]](Accuracy) → [[Bioresponse-진행기록|Bioresponse]](이진 LogLoss)
→ Otto(**9클래스 LogLoss**). 제출 5회, 최선 **Private 0.42649 (277위 / 3,509, 상위 7.9%)**.
AutoGluon 은 **0.41415 (68위, 상위 1.9%)**.

---

## 1. 스태킹이 이번 대회에서 가장 크게 벌었다

| 단계 | Private | 직전 대비 |
|---|---|---|
| lgbm 단일 | 0.48272 | — |
| fold 평균 | 0.47616 | −0.00656 |
| **스태킹** | **0.43937** | **−0.03679** |
| 리스태킹 | 0.42649 | −0.01288 |

**fold 평균의 5.6배를 벌었다.** 지난 대회에서 fold 평균이 효과적이어서 그걸 주무기로 생각했는데,
다중분류·대용량에서는 스태킹의 기여가 압도적이었다.

구조만 바꿨고 **1층 모델은 그대로다.** 6단계에서 저장해둔 OOF 를 재활용했을 뿐,
1층 재학습은 한 번도 안 했다.

> **OOF 는 점수 측정용이 아니라 자산이다.** 저장해두면 재학습 없이
> 블렌딩·스태킹·리스태킹을 전부 실험할 수 있다. 다음 대회에서도 무조건 저장한다.

## 2. 2층 모델은 선형이면 의미가 없다

| 2층 | OOF |
|---|---|
| 없음 (단순 평균) | 0.48532 |
| **LogisticRegression** | 0.48477 |
| **LightGBM** | **0.46400** |

로지스틱 회귀는 36개 피처의 선형 결합이라 **사실상 "학습된 평균"**이다. 평균과 0.0005 차이.
비선형 2층이 −0.0208 로 40배를 벌었다.

스태킹의 힘은 "가중치를 학습하는 것"이 아니라 **"조건부 규칙을 배우는 것"**에서 나온다.
`rf 혼자 다른 말 하면 rf 가 틀리더라` 같은 것.

## 3. CV−LB 갭은 모델이 아니라 **구조**에 따라 변한다

| exp | 갭 |
|---|---|
| exp01 단일 | +0.01458 |
| exp02 fold 평균 | +0.01777 |
| exp03 AutoGluon | +0.01118 |
| exp04 스태킹 | **+0.02627** |
| exp05 리스태킹 | **+0.03519** |

exp03 까지는 −0.011~−0.018 로 안정적이라 "이 대회는 갭이 일정하다"고 결론낼 뻔했다.
**스태킹을 얹자 갭이 2~3배로 벌어졌다.**

원인은 2층의 **입력 비대칭**이다.

```
2층 학습 입력 : 1층 OOF       = 4/5 데이터로 학습한 모델 1개의 예측
2층 제출 입력 : 1층 test 예측 = fold 5개 평균 (더 좋은 입력)
```

제출 때 더 나은 입력을 받으니 실제 성능이 OOF 보다 높다.
**스태킹을 깊게 할수록 이 격차가 증폭된다.**

실제로 OOF 에서 −0.00428 이던 리스태킹 효과가 LB 에서 **−0.0132, 3배**였다.

> [[Bioresponse-진행기록]] 교훈 2("한 점으로 일반화하지 않는다")가 또 맞았다.
> 다만 **모델 선택은 왜곡되지 않았다** — CV 순위와 LB 순위가 5개 전부 일치했다.
> 갭 크기는 틀려도 방향이 같으면 "더 나은 쪽 고르기"는 유효하다.

## 4. 익명 피처라고 EDA 가 쓸모없지 않다

93개 피처 의미가 전부 비공개라 도메인 지식을 쓸 수 없었는데, EDA 결론이 전부 적중했다.

| EDA 예측 | 실측 (lgbm OOF 손실 분해) |
|---|---|
| Class_2/3/4 가 닮음(상관 0.79~0.93) → 손실 집중 | **58.9% 차지** |
| feat_34 = Class_5 전용 마커 (eta² 0.64) | Class_5 손실 **1.0%** (최저) |
| Class_6 은 Class_2 와 다른 물건(상관 0.019) | 크기 비슷한데 기여 8.5% vs 22.9% |

**"어디서 점수를 잃는지" 를 먼저 알면 어디를 건드리지 말지도 알게 된다.**
Class_5 를 더 맞히려는 노력은 처음부터 의미가 없었다.

그리고 **train 이 target 으로 정렬돼 있는 것**을 EDA 코드를 다시 읽다 발견했다
(Class_1 → 행 0~1928, ... Class_9 → 56923~61877).
`shuffle=True` 없는 분할이면 CV 가 통째로 망가질 상황이었다.

## 6. 재현 실패를 반증으로 취급하면 안 된다

AutoGluon segfault 의 원인은 **macOS libomp 중복 로드**였다 — 알려진 이슈다
([pytorch#191933](https://github.com/pytorch/pytorch/issues/191933) ·
[LightGBM#6595](https://github.com/lightgbm-org/LightGBM/issues/6595)).

**이 가설을 한 번 세웠다가 버렸다.** 최소 재현 스크립트가 통과했기 때문이다.

```python
lgb.LGBMClassifier(...).fit(X, y)   # lightgbm 먼저
import torch                         # torch 나중
torch.jit.script(m)                  # → SURVIVED
```

그런데 **"torch 를 먼저 import 하면 괜찮다"가 알려진 동작**이었다.
내 재현 스크립트가 우연히 안전한 순서였던 것이다.

해결은 `OMP_NUM_THREADS=1` 한 줄. 그 전까지 7번 시도하며
신경망 제외·ray off·샌드박스 해제·DyStack off 를 전부 헛돌았다.

> **환경 문제를 의심하면 자력 디버깅 전에 검색부터 한다.**
> 동료 피드백 한 줄("맥 libomp 충돌 검색해보라")이 6번의 시행착오보다 빨랐다.
> 그리고 `KMP_DUPLICATE_LIB_OK=TRUE` 는 쓰면 안 된다 — 데드락을 유발한다
> ([pytorch#193520](https://github.com/pytorch/pytorch/issues/193520)).
> 실제로 별도 프로세스 predict 가 CPU 0% 로 2시간 44분 멈췄다.

## 7. 9클래스는 이진과 코드가 다르다

- `predict_proba` 가 `(n, 9)` 행렬 — 이진 습관의 `[:, 1]` 은 바로 버그
- fold 평균도 `(n, 9)` 로 0 초기화해야 함. broadcasting 으로 **조용히 통과**할 수 있다
- 기준점이 둘이다 — 균등 `ln 9 = 2.19722`(버그 탐지선)와
  **분포 엔트로피 1.95041**(피처가 일했는지 판정선). 불균형이 심할수록 후자가 훨씬 낮다
- 제출 열 순서는 `model.classes_` 순. `Class_1..Class_9` 는 사전순과 숫자순이
  **우연히 일치**할 뿐이다. 예측 클래스 분포를 train 분포와 대조해 간접 검증했다
- **같은 0.5 라도 의미가 다르다.** 이진에서 0.5 는 기준점(0.693)을 겨우 넘은 것이고,
  9클래스에서 0.5 는 기준점(2.197)을 크게 이긴 것이다. 지난 대회 숫자 감각을 가져오면 안 된다

## 8. AutoML 을 이기진 못했지만 격차의 정체는 알아냈다

```
시작   0.47616 vs 0.41415   −0.06201
최종   0.42649 vs 0.41415   −0.01234   (80% 축소)
```

리더보드를 읽으니 **AutoGluon 의 1층 모델은 내 것과 비슷한 수준**이었다
(LightGBM_BAG_L1 0.47084 vs 내 lgbm OOF 0.49180).
차이는 모델 품질이 아니라 **구조**였고, 구조를 따라가자 격차가 줄었다.

남은 차이:

| | 내 것 | AutoGluon |
|---|---|---|
| 1층 모델 | **4개 (전부 트리)** | 10개 (신경망·ExtraTrees·파라미터 변형) |
| 층 수 | 2층 | 3층 |

**1층 다양성이 가장 유력하다.** 내 1층은 전부 트리라 비슷한 실수를 한다.
다음에 1층에 선형·KNN·신경망을 섞어보면 이 가설이 검증된다.

## 다음 대회에서 먼저 할 것

1. **OOF 를 처음부터 저장한다** — 점수 측정용이 아니라 스태킹 자산이다
2. **AutoML 을 일찍 한 번 돌려 상한을 본다** — 내 베이스라인이 어디쯤인지 기준이 생긴다.
   그리고 **리더보드를 읽어 왜 좋은지 구조를 베낀다**
3. **새 환경은 `fit()` 전에 백엔드 import 테스트** — 조용한 실패를 비용 0으로 잡는다
4. **환경 에러는 자력 디버깅 전에 검색** — 대부분 알려진 이슈다
5. **CV−LB 갭은 구조가 바뀌면 다시 잰다** — 모델뿐 아니라 앙상블 구조에도 따라 변한다
