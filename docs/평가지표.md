# 평가지표 정리

대회마다 지표가 바뀌고, 지표가 바뀌면 **코드·모델 선택·판단 기준이 전부 따라 바뀐다.**
Titanic(Accuracy) → Bioresponse(LogLoss)로 오며 실제로 걸렸던 것들을 중심으로 정리한다.

---

## 0. 지표를 확인하면 바로 할 일

| 확인 | 왜 |
|---|---|
| **점수 방향** (↑ 좋음 / ↓ 좋음) | LogLoss·RMSE는 낮을수록 좋다. Accuracy와 반대라 계속 헷갈린다 |
| **`predict` vs `predict_proba`** | 확률 지표면 `predict`를 쓰는 순간 점수가 망가진다 |
| **sklearn `scoring` 문자열** | `neg_log_loss`, `roc_auc`, `neg_root_mean_squared_error` … |
| **기준점 계산** | "아무것도 안 한 제출"의 점수. 이보다 나쁘면 파이프라인 버그다 |

기준점 하나 계산해두는 것만으로 디버깅 속도가 달라진다.
Bioresponse에서 `all-0.5 = 0.69315`를 미리 구해두고 계속 대조했다.

---

## 1. LogLoss (Cross Entropy)

**확률을 제출하고, "정답에 매긴 확률"로 채점한다.**

### 정의

정답이 1인 문제에 0.85라고 답했다면 정답에 매긴 확률은 0.85, 벌점은 `-log(0.85) = 0.16`.
정답이 0인 문제에 0.85라고 답했다면 정답(0)에 매긴 확률은 0.15, 벌점은 `-log(0.15) = 1.90`.
이걸 전 행에 대해 평균 낸 것이 LogLoss다.

**이항:**
```
LogLoss = -평균( y·log(p) + (1-y)·log(1-p) )
```
y는 정답(0/1), p는 내가 낸 확률. y=1이면 앞항만, y=0이면 뒷항만 산다.

**다항 (k개 클래스):**
```
LogLoss = -(1/N) ΣᵢΣⱼ yᵢⱼ · log(pᵢⱼ)
```
각 행의 확률 합이 1이어야 한다. 정답 클래스에 매긴 확률만 벌점에 들어간다.
`predict_proba` 결과가 (N, k) 행렬이므로 **이항처럼 `[:, 1]` 하면 안 된다.**

### 왜 로그인가 — 확신한 오답을 가혹하게 처벌한다

| 정답에 매긴 확률 | 벌점 |
|---|---|
| 1.0 | 0 |
| 0.9 | 0.105 |
| 0.5 | 0.693 |
| 0.1 | 2.303 |
| 0.01 | 4.605 |
| 0.001 | 6.908 |
| 0 | **무한대** |

0.9 → 0.5는 벌점이 0.59 늘지만, 0.1 → 0.01은 2.3이 는다.
**"확실하다"고 외쳤는데 틀린 경우를 비선형적으로 처벌한다.**

정답에 확률 0을 주면 무한대라서, 실제 계산은 양끝을 조금 안쪽으로 민다.

```python
prob = np.clip(prob, 1e-15, 1 - 1e-15)
```

sklearn `log_loss`는 내부적으로 해준다. 직접 구현할 때만 신경 쓰면 된다.

### 기준점 계산법

**균등 확률 제출** — 모든 클래스에 1/k를 주면 `ln(k)`다.

| 클래스 수 | 균등 제출 LogLoss |
|---|---|
| 2 (이항) | ln 2 = **0.69315** |
| 9 (Otto) | ln 9 = **2.19722** |

**클래스 분포로 제출** — 학습 데이터의 클래스 비율을 그대로 일괄 제출하면
그 분포의 **엔트로피**가 나온다.

```
기준점 = -Σ pc · log(pc)        # pc = 클래스 c의 비율
```

Bioresponse는 54.23% / 45.77%라 `0.6896`이었다 (균등 0.69315보다 약간 낮다).
**불균형이 심할수록 이 기준점이 균등보다 많이 낮아지므로**, 다중분류에서는
`ln(k)`만 보지 말고 분포 기준점도 같이 구해야 한다.

```python
import numpy as np
# 이항
p = y.mean()
print(-(p*np.log(p) + (1-p)*np.log(1-p)))

# 다항
_, cnt = np.unique(y, return_counts=True)
pc = cnt / cnt.sum()
print(-(pc * np.log(pc)).sum())
```

### 코드에서 바뀌는 것

```python
# 학습·예측
oof[va] = model.predict_proba(X[va])[:, 1]        # 이항
oof[va] = model.predict_proba(X[va])             # 다항 (N, k)

# 교차검증
cross_val_score(model, X, y, scoring='neg_log_loss')   # 부호 주의: neg_
```

`scoring='neg_log_loss'`는 **음수를 돌려준다.** sklearn은 "클수록 좋음"으로 통일하려고
부호를 뒤집는다. 실제 LogLoss는 그 절댓값이다.

## 2. Accuracy · AUC · LogLoss — 뭘 재는가

| 지표 | 재는 것 | 확률값을 보나 |
|---|---|---|
| **Accuracy** | 맞춘 개수 | X (0/1로 자름) |
| **AUC** | 양성을 음성보다 높게 매겼는지 = **순위** | 순서만 본다 |
| **LogLoss** | 확률이 얼마나 정확한가 = **순위 + 보정** | 값 자체를 본다 |

Accuracy는 0.51로 맞힌 것과 0.99로 맞힌 것을 똑같이 센다.
AUC는 모든 확률에 같은 변환을 걸어도(예: 전부 반으로) 점수가 안 변한다. 순서만 보기 때문이다.
**LogLoss만 확률의 절대적인 값을 본다.**

### AUC는 좋은데 LogLoss가 나쁠 수 있다

Bioresponse에서 실제로 관찰한 것:

| 모델 | AUC | LogLoss |
|---|---|---|
| rf | 0.859 (1위) | 0.4781 |
| catboost | 0.856 | **0.4709** (1위) |
| **xgboost** | **0.853** (상위권) | **0.5960** (최하위권) |
| lr | 0.793 | 0.6708 |

xgboost는 **순위는 잘 매기는데 확률값이 치우쳐 있었다.**
AUC나 Accuracy였다면 안 드러났을 문제가 LogLoss에서는 그대로 손실이 된다.

**AUC로 모델을 고르고 LogLoss로 제출하면 틀린 모델을 고른다.** 지표를 통일해서 비교해야 한다.

## 3. 확률 보정 (Calibration)

"예측 확률 0.7인 것들을 모아보면 실제로 70%가 양성인가?"
그렇다면 **보정이 잘 된(calibrated) 모델**이다.

| 모델 | 경향 |
|---|---|
| Logistic Regression | 보정이 잘 되는 편 |
| CatBoost | 비교적 잘 되는 편 |
| RandomForest | 극단값(0, 1) 쪽으로 잘 안 간다 — 투표 비율이라서 |
| XGBoost / LightGBM | 설정에 따라 과신하기 쉽다 |

보정이 어긋나면 **LogLoss에서만** 손해를 본다. AUC는 그대로다.

### 보정을 더한다고 늘 좋아지지 않는다

Bioresponse 03에서:

| | LogLoss |
|---|---|
| catboost 원본 | **0.4700** |
| catboost + sigmoid 보정 | 0.4751 |

**이미 보정이 잘 된 모델에 보정을 덧씌우면 나빠진다.**
`CalibratedClassifierCV`를 기본값처럼 끼얹지 말고, 넣은 것과 뺀 것을 같은 체계로 비교해야 한다.

보정 방법은 보통 두 가지다 — **sigmoid(Platt scaling)**: 로지스틱 곡선을 씌운다, 데이터가 적을 때 안정적.
**isotonic**: 단조 증가 계단함수를 맞춘다, 유연하지만 데이터가 많아야 한다.

## 4. 회귀 지표

| 지표 | 정의 | 성격 |
|---|---|---|
| **MAE** | 평균 절대오차 | 이상치에 둔감 |
| **RMSE** | 평균 제곱오차의 제곱근 | 큰 오차를 제곱으로 키움 → **이상치에 민감** |
| **RMSLE** | log(1+y)에 RMSE | **비율 오차**를 본다. 과소예측에 더 가혹 |
| **R²** | 분산 설명 비율 | 높을수록 좋음 (방향 반대) |

**RMSLE가 쓰이면** 타깃을 `log1p`로 변환해 학습하고 예측 후 `expm1`로 되돌리는 게 정석이다.
그러면 모델이 푸는 문제가 RMSE가 되어 최적화 대상과 평가지표가 일치한다.

집값·매출처럼 **값의 스케일이 수십 배 차이 나는 타깃**에서 RMSLE를 많이 쓴다.
"1억을 2억으로 틀린 것"과 "10억을 11억으로 틀린 것"을 RMSE는 같게 보지만 RMSLE는 다르게 본다.

## 5. 지표별 요약

| 지표 | 방향 | 제출 형태 | sklearn `scoring` | 기준점 |
|---|---|---|---|---|
| Accuracy | ↑ | 클래스 | `accuracy` | 다수 클래스 비율 |
| AUC | ↑ | 확률/점수 | `roc_auc` | 0.5 (무작위) |
| LogLoss | ↓ | 확률 | `neg_log_loss` | ln(k) 또는 분포 엔트로피 |
| RMSE | ↓ | 값 | `neg_root_mean_squared_error` | 타깃 평균 예측 시 = 표준편차 |
| MAE | ↓ | 값 | `neg_mean_absolute_error` | 타깃 **중앙값** 예측 |
| RMSLE | ↓ | 값 | (직접 구현) | log 공간의 평균 |

> MAE의 최적 상수 예측은 평균이 아니라 **중앙값**이다. RMSE는 평균이다.
> 지표가 바뀌면 "아무 생각 없이 낼 최선의 값"도 바뀐다.

## 실제로 걸렸던 것 (Bioresponse)

1. CV를 `scoring='neg_log_loss'`로 바꾸는 건 기억했는데, **점수 방향이 반대**인 걸
   계속 헷갈렸다. 표를 만들 때마다 "낮은 게 1위"를 확인해야 했다
2. **기준점 0.69315를 먼저 구해둔 게 가장 유용했다.** 결과가 이상할 때마다 대조했다
3. **AUC 1위와 LogLoss 1위가 다른 모델**이었다. 비교표를 AUC로 정렬해놓고 LogLoss로
   고르면 틀린다
4. 보정이 잘 된 catboost에 sigmoid를 **더해서 나빠졌다**
